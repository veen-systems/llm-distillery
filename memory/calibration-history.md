# Calibration History

Long-arc record of scorer training, calibration, and oracle-prompt experiments — what worked, what didn't, and what shouldn't be retried. Loaded when calibration work starts.

## What lives here vs elsewhere

Per the governance schema in ducroq/llm-distillery#69:

| Category | Lives in |
|---|---|
| Scorer training, label-set, hard-negatives, oracle prompts | **this file** |
| Pipeline prompt behaviour (brand-voice, gate, summarization) | `ovr.news/docs/hypothesis-log.md` Dead Ends |
| Infrastructure, deployment, GPU contention, model loading | `ovr.news/memory/infra.md` and `vmodel.eu/memory/gotcha-log.md` |
| Architecture / ADR-superseding decisions | `docs/adr/` (Superseded ADRs) |

Cross-link, don't duplicate: when a scorer retrain was triggered by a pipeline-prompt issue, each side has a one-line pointer to the other; the substance lives in whichever repo owns it.

## Dead Ends (don't retry these)

Compact "what we tried, why it failed, don't retry" entries. Pattern adopted from the vmodel pattern cluster — see [ducroq/agent-ready-projects#16](https://github.com/ducroq/agent-ready-projects/issues/16) for the cross-repo tracker. Sibling adoptions: [ovr.news commit 6132725](https://github.com/ducroq/ovr.news/commit/6132725) (shipped 2026-06-05), [ducroq/NexusMind#230](https://github.com/ducroq/NexusMind/issues/230) (pending).

- **Selecting adverse / hard-negative training examples LEXICALLY — FOR THE THRIVING FAMILY** (2026-09-09, NexusMind-reported, llm-distillery#156 / v9 data design). … ⛔ **The mechanism is structural, not a tuning problem: an uplifting story about overcoming adversity NECESSARILY NAMES THE ADVERSITY**, so a lexical harm filter preferentially surfaces redemption and resilience narratives — precisely the lens's core competence. A keyword-mined hard-negative set would train the model to score DOWN the articles it exists to find. **Don't retry** keyword/regex selection of ADVERSE EXAMPLES for `uplifting`/`human_thriving`; there, selection needs a **judge**, not a filter. ⛔ **SCOPE — this does NOT forbid keyword work generally, and two live uses are explicitly out of scope:** `memory/violence-promotion-v1-hypotheses.md`'s v2 corpus strategy (keyword-selected corpus, planned and alive) and `BasePreFilter`'s `EXCLUSION_PATTERNS`/`OVERRIDE_KEYWORDS` under ADR-018/019, which DO run in the oracle/training path. The mechanism cited is **lens-specific** — it depends on recovery narratives being this lens's core competence — and does not transfer to `investment_risk` or `nature_recovery` (the EXP-031 harm rubric is one — blind, pre-registered, belongs to neither lens's oracle). ⚠️ **Reported, NOT adjudicated** — the 66 were never labelled, so *"none of them is adverse"* is a reading of the top of the list, not a measured false-positive rate; the durable claim is the mechanism. ✅ Verified 2026-09-09 that nothing in this repo's v9 path does lexical selection: `filters/human_thriving/v8/` has **no `prefilter.py`** (ADR-018 as amended 2026-08-21 — new filters ship none, keyword screening being Latin-script only), and `training/prepare_data.py` / `scripts/merge_training_data.py` contain no keyword or regex selection. **Cross-ref:** `H-AP6` in `memory/archive/hypothesis-ledger-archive.md` (closed rows moved 2026-09-27); the counterpart positive finding is `H-AP5` — the labelled corpus cannot hold the failure mode at all, so the pool must come from production. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Pure embedding + linear/MLP probe as substitute for fine-tuning** (uplifting v5 comparison, 2026-01). … **Don't retry** replacing the fine-tuned student with frozen-embedding + probe for nuanced multi-dimensional regression — embeddings capture topic, not quality. Commerce binary classification is the exception (embeddings won 98.3% vs 97.8% F1, kept as `base_prefilter`). *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Naive PyTorch dynamic INT8 quantization on Gemma-3-1B** (#24, 2026-03-07). … **Don't retry** `torch.quantization.quantize_dynamic` as a one-line speedup — it nearly doubles MAE. The remaining viable paths on #24 are ONNX Runtime calibrated INT8, GGUF / llama.cpp, or smaller base-model retrain (Qwen2-0.5B uplifting reached MAE 0.760, see `docs/OPEN_QUESTIONS.md`). *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Orthogonal-lens prompt design** (thriving v1, 2026-03 → PARKED 2026-04). … **Don't retry** "this is NOT [other lens], score 0–2" exclusion clauses in oracle prompts, and don't strip glue dimensions (e.g. `social_cohesion_impact`) trying to enforce orthogonality — lenses are overlapping perspectives, and ADR-014 percentile normalization handles cross-tab ranking already. **Cross-ref:** structurally the same lesson as [ovr.news hypothesis-log](https://github.com/ducroq/ovr.news/blob/master/docs/hypothesis-log.md) Dead Ends entry "Stack rules in the brand-voice prompt" (#229, 2026-06-01/02) — adding rules surfaces new failure modes, not fewer. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **`score_scale_factor` linear stretch as cross-filter normalization** (Mar 2026, superseded by ADR-014). … **Don't retry** any global linear or moment-based normalization (`score_scale_factor`, z-score, P99 max-scaling, val-set CDF) as cross-filter harmonization. `score_scale_factor` remains only as the fallback path for filters that don't yet have `normalization.json`. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Universal noise prefilter beyond commerce** (sustainability_technology active learning, 2026-01-31). … **Don't retry** building a second "universal noise filter" for software / farming / policy. Accept ~30–40% oracle waste during training — the "wasted" zeros are valuable negative training examples for the student. Use filter-specific keyword prefilters + per-filter student scope. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **`% normalized < 0.5` as a filter-health metric** (LD#76 audit, 2026-07-31). … **Don't retry** `% norm < 0.5` (or any below-op-point share) as a filter-health headline — it conflates base rate with pathology. Use the ir-derived criteria instead: raw p90 vs op-point, populated spread-out MEDIUM+ band, intact good-vs-chaff separation, anchored fresh fit. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Diagnosing raw-score health from production files without checking score provenance** (#75, falsified by LD#76 audit 2026-07-31). … **Don't retry** reading a hybrid filter's raw production distribution as a model signal without first splitting rows by inference stage (until `stage_used` is emitted: probe-capped values cluster at the stage-1 threshold) and checking `normalization_method` on the rows you're aggregating. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **`.nexusmind-owns` manifest as cross-repo divergence-management strategy** (#50, 2026-04-28 → retired 2026-05-04). … **Don't retry** an "X is owned by the other repo" manifest as the *primary* divergence-management mechanism — default to extraction (composition over inheritance, wrapper classes). "By design" is a claim about the implementation; verify by reading the runtime, not the design doc. **Cross-ref:** same family as ovr.news hypothesis-log Dead Ends entry "NexusMind embedding-dedup as sole source of truth" (corroboration cluster, seeded 2026-06-05) — both are cases where a shared assumption between repos was load-bearing but never verified at runtime. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Treating a filter's `config.yaml` as evidence that the thing it configures is running** (NM#284, 2026-08-01). … **Don't retry** inferring runtime behavior from config keys, and don't accept "the config says enabled" as verification. **The diagnostic that settles it:** measure the component *in-path on the pre-drop stream* — the shadow log reports cd `observed_pass` 0.255 pooled at the scorer, which would read ≈1.000 if the gate were enforcing upstream. **Don't retry** the more tempting version of this: replaying the component over rows from `data/filtered/*/filtered_*.jsonl` and diffing against the stamped rate. That file only receives rows where `passed_prefilter` is true NexusMind `scripts/main.py`’s `if result["passed_prefilter"]:` write guard, so its "100% passed" is an artifact of the file's own write condition — the first version of this entry cited exactly that and had to be retracted. **A reproduction is only as good as the population you reproduce it on; before using a data source as a denominator, establish what it is filtered on.** Generalizes to any declared-rate component: assert observed against declared in production, or the declaration is decoration. Same family as the `.nexusmind-owns` entry above and `memory/gotcha-log.md` "LD#80 rollback was a production no-op" — verify the call path, not the diff. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Reading a lens-specific block rate off a prefilter without splitting out the shared base rules** (NM#284 sizing, 2026-08-01). … **Don't retry** quoting a prefilter's total block rate as lens signal — always split base-class rules (length, missing content) from lens rules first. Corollary correction: nature_recovery v4's zero lens blocks are *deliberate and documented* (v4 removed topic/decline gates — English-only, cost 21.6% recall — delegating screening to the multilingual e5 probe), so "lens block rate must be non-zero" is the wrong harmonization criterion. The right one is **observed pass rate matches declared, and `description` matches actual behavior** (LD#90). *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **A global pre-fan-out `content_too_short` gate** (NM#284 stage 2 proposal, 2026-08-01 → REFUTED 2026-08-02). … **Don't retry** promoting `MIN_CONTENT_LENGTH` to a gate at any level. The one filter with a genuine short-content defect (`solutions v6`, DiD −1.13) wants a **cap/penalty** sized to its own ~49 FPs per 8 cycles — see #93 and `memory/prefilter-length-floor-hypotheses.md`. **#93 shipped 2026-08-03 (LD side):** the floor is now labelling-time only, length is stamped on every scoring result, and a per-filter `short_content.cap` exists — **set on nothing**, because solutions' DiD is still confounded with a selection artifact. Fitting that cap without the second-op-point re-run would be the same mistake one level down. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **Explaining the six-filter prefilter pass-rate cluster as a truncation artifact** (NM#285, 2026-08-01 → REFUTED 2026-08-02). … **Don't retry** widening the GPU `Article` contract (Option A) or moving prefilters pipeline-side (Option C) *on truncation grounds* — both were declined on this measurement. A separate, larger bias does exist in the same log: the denominator counts articles `source_filter` discards after scoring (−0.129 on investment_risk), now stated on every shadow line. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **MAE as a cross-filter quality metric — and as grounds for any calibration change** (2026-08-09, killed by the owner within an hour of being published). … **Don't retry** ranking filters on MAE, or changing a calibration on an MAE reading. **The same trap one level down: precision is base-rate dependent too.** Only **recall** and **specificity** are conditional on the true class and comparable across splits — report both, always with the split's positive rate. Now **ADR-023** and a CLAUDE.md Hard Constraint. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

- **"The isotonic calibrator crushes the scale" as the explanation for the 173× cross-lens surfacing spread** (2026-08-09, proposed and refuted the same day by the agent that proposed it). … **Don't retry** explaining a low surfacing rate by a calibration pathology before oracle-grading a *stratified sample of the actual production distribution* — a mechanism can be real, measured, and still not be the lever. And **don't read a needle filter's low surfacing count as a defect at all** until the base rate is established: the outlier in that table was `investment_risk` at 24.2%, not `nature_recovery` at 0.14%. *(Full entry: [archive](archive/calibration-history-archive.md#moved-2026-10-19-163-round-10).)*

## Maintenance

- Add an entry when an experiment is concluded as "don't retry" (not "paused — may revisit"). Paused experiments belong in `memory/thriving-v1-scoring.md` (and similar) or in an ADR; they should only land here once the door is closed.
- Keep entries to one paragraph (3–5 sentences). If the entry grows a multi-step rationale, link out to an ADR or gotcha-log entry instead of inlining it.
- The `**Don't retry** <scope> — <reason>` closing is mandatory; that's the line a future agent reads at session start to avoid the re-experiment.
- Reviewed as part of end-of-session `/curate` flow: "did any approach fail today that future-you should not retry?"
